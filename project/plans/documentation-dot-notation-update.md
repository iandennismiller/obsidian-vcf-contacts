# Documentation Update: Dot Notation Migration

## Problem Statement

The repository documentation contains inconsistent references to key generation logic. Many documents still reference the old bracket notation (e.g., `RELATED[friend]`, `EMAIL[WORK]`) when the current implementation now uses YAML-compatible dot notation (e.g., `RELATED.friend`, `EMAIL.WORK`) generated by standard libraries.

The project has migrated to using:
- **yaml library**: For YAML parsing and generation
- **flat library**: For object flattening/unflattening
- **vcard4 library**: For vCard parsing and generation
- **marked library**: For markdown parsing

This means much of the custom parsing logic described in older documentation has been replaced by these libraries, but the documentation hasn't been updated to reflect this.

## Analysis

### Files Using Bracket Notation (Old)

**Specifications:**
- `project/specifications/vcf-sync.md` - References `RELATED[type]`
- `project/specifications/gender-processing.md` - References `RELATED[parent]`
- `project/specifications/contact-section.md` - References `EMAIL[WORK]`, `TEL[HOME]`, etc.

**Documentation:**
- `docs/demo-data/README.md` - Mixed notation (shows bracket in some examples)
- `docs/development/setup.md` - References `RELATED[parent]`, `RELATED[colleague]`

### Current State (Code vs Docs)

**Code Reality:**
- The code in `src/models/contactNote/syncOperations.ts` is **generating bracket notation** (lines 135-136, 143-144)
- The code in `src/models/contactNote/relationshipOperations.ts` is **converting dot notation TO bracket notation** (auto-correction)
- This means the code is NOT using the yaml library's natural dot notation capabilities

**What Should Happen:**
- YAML library naturally supports dot notation: `RELATED.friend.0`, `RELATED.friend.1`
- flat library should handle the flattening/unflattening
- Frontmatter should use dot notation throughout
- Documentation should describe this natural library behavior

## Root Cause

The issue is **NOT just in documentation** - the implementation itself needs to change:
1. The code is manually generating bracket notation instead of letting yaml/flat handle it
2. The documentation describes both old bracket notation and newer dot notation inconsistently
3. The library-integration-spec correctly describes the libraries but other specs contradict it

## Dot Notation Examples

### Correct Format (Dot Notation)
```yaml
# Single relationships
RELATED.spouse: urn:uuid:12345...
RELATED.friend: urn:uuid:67890...

# Multiple relationships of same type (flat library auto-indexes)
RELATED.child.0: urn:uuid:aaaaa...
RELATED.child.1: urn:uuid:bbbbb...
RELATED.child.2: urn:uuid:ccccc...

# Structured fields
N.GN: John
N.FN: Doe
EMAIL.WORK: john@work.com
TEL.CELL: +1-555-1234
ADR.HOME.STREET: 123 Main St
ADR.HOME.CITY: Springfield
```

### Incorrect Format (Bracket Notation - OLD)
```yaml
# Don't use these formats
RELATED[spouse]: urn:uuid:12345...
RELATED[friend]: urn:uuid:67890...
RELATED[child]: urn:uuid:aaaaa...
RELATED[1:child]: urn:uuid:bbbbb...
EMAIL[WORK]: john@work.com
TEL[CELL]: +1-555-1234
```
